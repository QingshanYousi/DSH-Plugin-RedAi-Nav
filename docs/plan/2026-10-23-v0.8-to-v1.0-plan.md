## 2. 批次 A · 可读性收口（0.7.1，4h）

> **状态：已完成，0.7.1 定版**（2026-10-23，QA 三轮复验 PASS）。六类徽章四列最差 **5.33**（普通卡 hot 亮 hover）、归档卡最差 **5.80**，色相漂移 ≤1°；11 个控件命中区均 ≥28px；`type=search` 已改自绘清除；断言 286 → **324**；`lib/client.js` 2091 行。
>
> **本轮沉淀的三条规则**（下批沿用）：
> 1. 徽章类「彩色文字 + 同色淡底」的对比度必须按**合成后底色**算，按页面底色算会得出错误结论；且加深底色会让对比**下降**，达标只能压深文字。对比度表必须是四列：亮常态 / 亮 hover / 暗常态 / 暗 hover——漏掉 hover 叠加面会得出"最差 4.78"这种错误结论（真实最差 4.18）。
> 2. `inset` / `top` / `bottom` / `left` / `right` 全部相对 **padding box** 计算。带 0.5px 描边的控件用边距撑 28px 命中区会正好少 1px，必须改用 `width/height:28px` 硬锚定。
> 3. 量 `getComputedStyle` 前必须处理 `transition`：`.redaiPluginCard{transition:background .12s}` 会让切主题后的第一帧读到过渡中间色，算出假失败（实测曾测出 1.19:1）。切主题/伪类后等 ≥400ms 或临时 `transition:none` 再读。
>
> **降透明度这条路走不通**（重要）：`opacity` 会把徽章自己那层 18% 淡底一起往页面色拉，要让最差项过 4.5 需要 **0.97（亮）/0.99（暗）**，等于没有弱化信号。弱化要用「灰底 + 淡边框 + 徽章」承担，不要用整棵子树透明。

> 这批改的是"看得清"，不改结构，风险最低，可独立发一版。

**A1 的取值（决策 D1 已定：保色相 + 提字号，文字压深到刚好过线）**

> 先纠正一个数学前提：徽章是「彩色文字 + 同色淡底」，把底色 alpha 从 12% 提到 18% 会让底色向文字色靠拢，**对比度反而下降**；11px 也不构成 WCAG 的"大文本"（需 18.66px 粗体才放宽到 3.0）。因此"只提字号+加深底色"单独执行永远到不了 4.5。落地口径 = 色相不变，文字取同色系里**最浅但 ≥4.5** 的深色，同时字号 10→11px、底色 12%→18%（视觉更沉但不换色系）。

| `new` | `#2f9e68` 2.71 / 3.86 | `light-dark(#14603c,#5fd39b)` | 同上 |

## 9. 风险登记

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| B4 改结构导致中键/Ctrl 打开失效 | 中 | 高（开发者高频操作） | 先补 3 条断言再改代码；采纳 D2 选项②可基本规避 |
| 徽章改色引发"这不是原来的插件"观感 | 中 | 中 | A1 出改动前后对比截图，随 PR 附上；保留一键回滚（单次提交） |
| 容器查询在 Electron 内核版本上不支持 | 低 | 中 | 先探测 `CSS.supports('container-type','inline-size')`，不支持则退回 `@media` + `ResizeObserver` 方案 |
| FLIP 与 88 卡片重排叠加导致掉帧 | 低 | 中 | FLIP 只用于插件榜 12 条；站点列表不做 FLIP |
| 数据抓取撞 GitHub 配额（60/h，一次 --check 要 24 次） | 高 | 低 | CI 里只跑 `--offline`；写入模式人工每两周一次 |
| 拆分后测试迷你运行时 hook 槽按位置分配（R-5） | 中 | 中 | 加状态类测试前先改成按 key 分配，否则"筛选后逐卡状态"会串 |

## 12. 联网能力的准入规则（2026-10-23 定位调整后新增）

对外口径从「单文件 / 离线」改为「**本地优先 · 出网可声明**」。这不只是文案：离线不再是身份，而是默认行为。任何联网能力进代码前必须满足下面五条，缺一条就不合并。

| # | 规则 | 怎么被验证 |
|---|---|---|
| 1 | **出网必须申报**：域名与用途先写进 `dsh.disclosure.network`，CI 会拦「代码有 `fetch` 而声明为空」，也会拦「声明了但代码不调用」 | `.github/workflows/ci.yml` 的 network 门禁，双向检查 |
| 2 | **可单独关闭**：每个联网能力有独立开关（设置项或菜单项），关掉后功能退化为本地数据，不报错 | 关掉后走一遍该功能，UI 不出现加载态死循环 |
| 3 | **失败必须降级**：请求超时/断网时用上一份本地数据渲染，并明示「数据更新于 X」，不允许空屏 | 断网跑一次预览，页面仍能出站点与插件卡 |
| 4 | **不出网即不采集**：不得为了埋点、统计、A/B 而发请求；每个出网域名必须能一句话说清"为什么非它不可" | code review 逐条过 `network` 数组 |
| 5 | **界面上可见**：联网时用户能在同一屏看到"正在联网/已更新于"，不用去翻 README | 该功能的加载与更新态截图 |

对应到 CI：门禁从「禁止网络」变成「申报一致」，这条改动已落地——它允许联网，但让**偷偷联网**变成不可能。

**唯一不跟着放宽的两条**：零第三方依赖（供应链面）、零宿主端代码（权限面）。这两条不是定位，是攻击面控制。

### 12.1 对外宣传口径（2026-10-23 二次修正）

**卖点只有产品功能**，一句话说清"它替你省了什么"，而不是"它不做什么"。

| 层级 | 写法 | 反例（不要再写） |
|---|---|---|
| 首屏 | 88 个站点 / 8 组 / 搜索 + 键盘直达 / 星标 / 插件榜 | 「单文件」「离线」「不联网」 |
| 次要 | 零宿主端代码、零第三方依赖（作为"敢让你审计"的支撑句，不单独成句） | 「本地优先 · 出网可声明」这种把网络当卖点的写法 |
| 技术附录 | 权限声明表里一行 `联网策略` + `disclosure` 字段说明 | 在 banner、首屏、宣传图里讲联网 |

判断标准：**把「联网」两个字从文案里删掉，产品价值是否还完整**？完整就对了——联网是工程约束，不是卖点。
